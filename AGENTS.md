# Contributor instructions

Keep this repository limited to reusable Pico source code, tests, documentation and generic assets. Runtime data belongs in the user's Application Support folder, outside the checkout. Never commit recordings, transcripts, screenshots, learned corrections, credentials, local preferences, personal agent skills or private workflows.

Before every push, release or other upload, obtain the repository owner's explicit approval of the exact proposed contents and destination. A development request is not publication approval. Review all newly exposed history as well as the final tree, including untracked candidate files and binaries. Prepare an exact commit/file manifest, state exclusions and unresolved findings, then stop for approval. If contents or destination change, repeat the review. Do not automate uploads or bypass this gate through scripts, hooks or delegated work.

Preserve local user data and customizations. Do not silently delete data or rewrite history to prepare a clean release; make a separate reviewed snapshot when needed. Test with temporary synthetic data, and do not interrupt an active recording during installation.
